# LifeBridge Constitution

## Core Principles

### I. Safety First (NON-NEGOTIABLE)
AI output MUST NEVER be presented as a diagnosis, definitive medical advice, or final legal authority. Every high-risk action generated by LifeBridge MUST display an explicit confidence score, cited factual sources, and a prominent, unambiguous "verify with a professional" advisory. If danger or clinical urgency is ambiguous, the system MUST default to the safest escalation path.

### II. Structured Output Only
All generative model outputs MUST conform strictly to predefined JSON schemas enforced via `response_schema` at the API boundary. Model responses MUST be validated with Pydantic (backend) and Zod/TypeScript contracts (frontend) prior to reaching user-facing components or execution layers. Free-form, unvalidated raw LLM strings MUST NOT be rendered directly as actionable items.

### III. Verification Over Generation
Factual claims—including drug interactions, emergency facility locations, weather advisories, hazard levels, and traffic conditions—MUST be grounded in Google Search, Google Maps/Places grounding, or vetted external APIs. Every factual assertion MUST link to verifiable citations. Unverified claims MUST be explicitly tagged with a status of `unverified` or `conflicting` and accompanied by verification warnings.

### IV. Multimodal by Default
The application MUST ingest voice recordings, live audio, images (medicine packaging, prescriptions, hazards, handwritten notes), documents (PDF medical summaries, lab discharge sheets), and pasted text through a single unified ingestion pipeline. All modalities converge into a standardized extraction and verification workflow.

### V. Privacy & Data Minimization
LifeBridge operates on a zero-storage principle by default: personal data, medical records, and user inputs MUST NOT be persisted to a permanent database without explicit runtime consent. All server logs and telemetry MUST sanitize and redact Personally Identifiable Information (PII) and Protected Health Information (PHI). A clear, accessible privacy and consent notice MUST be visible prior to input processing.

### VI. Accessibility & Multilingual Inclusivity
The user interface MUST be mobile-first, responsive, and compliant with WCAG AA contrast and sizing standards, featuring generous touch targets for high-stress scenarios. The system MUST support voice input and speech synthesis output, plain-language formatting, and localized support for English, Hindi, and Marathi.

### VII. Graceful Degradation & Active Clarification
When input ambiguity prevents high-confidence triage, the model and rules engine MUST NOT hallucinate or guess. The system MUST fall back gracefully, presenting static emergency guidance (such as emergency calling buttons) and asking targeted clarifying questions to resolve missing critical variables.

### VIII. Simplicity & Secret Hygiene
The codebase MUST remain lightweight, demo-ready, and maintainable without unnecessary microservice overhead. The repository MUST remain strictly secrets-free: no API keys, credentials, or production tokens committed, relying exclusively on `.env.example` templates and standard environment variables. Complete containerization via Dockerfile and docker-compose MUST be maintained.

## Technology Guidance & Standards

- **Backend**: Python FastAPI with Pydantic v2 schemas and Google Gen AI SDK.
- **Frontend**: React + Vite with Tailwind CSS (mobile-first, PWA-ready).
- **AI Models**: Gemini API (`gemini-2.5-flash` or the latest stable available model) leveraging multimodal inputs, structured JSON output (`response_schema`), and Google Search/Maps grounding.
- **Voice Fallbacks**: Web Speech API integration in the browser paired with server-side audio ingestion.
- **Containerization**: Standard Dockerfile and `docker-compose.yml` compatible with Cloud Run and AWS free-tier hosting.

## Quality & Governance Gates

1. **Deterministic Escalation Rules**: In addition to AI reasoning, a deterministic heuristic layer MUST inspect inputs for critical red-flag keywords (e.g., chest pain, unresponsive, severe bleeding, flash flood) and force severity escalation regardless of model output.
2. **Offline-Safe Emergency Fallback**: A static emergency card with regional critical helpline numbers (112, 108, 102 for India) MUST be immediately accessible without network connectivity.
3. **Review & Amendment**: Any alteration of these principles requires documentation in the Sync Impact Report and a semantic version increment.
